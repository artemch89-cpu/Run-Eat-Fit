# Run Eat Fit — спека MVP

Дата: 2026-09-07. Собрано за одну сессию (рыночный анализ → архитектура → discovery-интервью).

## Идея

Telegram-бот — персональный AI-тренер с памятью о жизни пользователя. Не калькулятор калорий (эта ниша занята — Calorie AI, FoodScan, FitPlate, FitnessAI Bot), а живой коуч, который держит контекст: тяжёлый день на работе, перелёт, чей-то день рождения — и учитывает это в общении и плане.

## Гипотеза, которую проверяем

Люди будут <b>ежедневно общаться</b> с таким ассистентом. Не «понравится ли идея», а реальное ежедневное возвращение. Оплата — вторичная проверка (гипотеза цены: 300–400 ₽/мес), но не главная метрика MVP.

Числовую метрику успеха (X% из Y пользователей N дней подряд) сознательно не фиксировали — приоритет: запустить быстрее, проверить на практике, скорректировать по ходу.

## Аудитория

Русскоязычные релоканты в Сербии — активные, часто без детей. Не сербы. Сербский язык — фича для локального доверия, добавляется позже, не в MVP. Осваивать сегменты постепенно: сначала общая аудитория, отдельно — семьи с детьми-спортсменами как режим/настройка (не отдельный продукт).

## Core loop (обязательно в MVP)

Петля привычки, не просто «бот отвечает, если написали»:
1. <b>Триггер</b> — бот пишет первым в выбранное пользователем время
2. <b>Минимальное действие</b> — максимально низкий порог входа (например «одним словом — как ты сегодня»), не «отчитайся о тренировке»
3. <b>Награда</b> — подстроена под стиль общения (строгий/мягкий — спрашивается при онбординге)
4. <b>План на срыв</b> — пропустил день → бот не молчит с укором и не ругает, мягко возвращает («бывает, сегодня по силам сделать по минимуму?»)

## Функциональность MVP

<b>Онбординг:</b> цель (похудение / бег / подтягивания / другое), вид спорта/активности, стиль общения (строгий / тренер-партнёр / мягкий — добавлен третий вариант по итогам живого теста 08.09.2026, живее двух крайностей), удобное время для чек-ина.

<b>Память:</b> простая БД (не векторная, не RAG — объём памяти на юзера маленький, в духе MEMORY.md). Никаких отдельных серверов на пользователя — это одна и та же модель API, данные это просто текст в базе, подставляемый в промпт.

<b>Тренировочные планы — гибридная модель:</b>
- 2 профиля нагрузки на старте (выносливость, силовая) — не 4 и не 150 видов спорта. Расширяются по факту спроса
- Модель строит план, опираясь на курируемые методички (skill-документы: прогрессия нагрузки, разминка, питание, восстановление) — не на голых знаниях модели и не на GitHub-репозиториях (звёзды на GitHub не показатель качества методики)
- Бот — конditioning/lifestyle-коуч вокруг любого спорта (калории, разминка, питание, восстановление), не техника конкретного вида спорта — под это не нужна экспертиза в каждом виде
- Запрос вне охваченных категорий → общие принципы + уведомление Артёму + модель готовит черновик новой методички на основе веб-поиска по авторитетным источникам → Артём вручную проверяет и публикует (человек в цикле обязателен — без этого теряется главная защита от плохого совета)

<b>Фото еды:</b> в MVP входит (осмысленно — название бота обязывает, питание напрямую влияет на форму). Haiku 4.5, стандартное разрешение фото (не high-res режим — дороже в 3 раза, для этой задачи не нужен).

<b>Модели (обновлено 09.09.2026):</b> Haiku 4.5 для диалога с коучем — по итогам живого теста качество устраивает, дешевле Sonnet 5. Для фото еды модель пока не выбрана — экспериментируем на реальных фото (см. `research/test-photos/`), возможен и Sonnet 5.

<b>Оплата:</b> вручную, переводом, для первых 20–30 знакомых. Никакой автоматической платёжной инфраструктуры в MVP.

## Явно ВНЕ MVP (второй круг)

- Кроссплатформенность (Viber) — Telegram-only на старте
- Геймификация с блокировкой приложений (Duolingo-style) — требует нативного приложения, не бот
- Подключение умных часов / Strava — не нужно для проверки главной гипотезы, отдельная инженерная задача (OAuth с каждым сервисом)
- Автоматическая мультивалютная оплата (Россия + Европа) — юридический вопрос (ИП в разных юрисдикциях), нужен бухгалтер/юрист, не блокер для теста на знакомых
- Полностью автоматическая AI-генерация плана без ограничения на категории (вариант «Б» в чистом виде) — отклонили: риск для здоровья без проверки корректности, нет способа проверить качество без эксперта в каждом виде спорта

## Технические решения

- Стек: Node.js Telegram-бот (по аналогии с существующей инфраструктурой), Claude API (Sonnet 5 + Haiku 4.5), простая БД (не векторная)
- Экономика: ≈ $1.5–2 AI-costов на активного юзера в месяц при цене 300–1000 ₽/мес — маржа здоровая, себестоимость компьюта не узкое место
- Кэширование промпта: разделить общую личность коуча (кэшируется через всех юзеров) и память конкретного юзера (кэшируется только внутри его сессии) — экономия за счёт масштаба, не критична для одного юзера

## Оценка сроков

≈ 3–4 недели по 1.5 часа в день (~20–25 рабочих сессий) при условии не отвлекаться на пункты из списка «вне MVP». Главный риск по срокам — не код, а (1) качество методичек под профили нагрузки, требует вычитки, не генерируется за 5 минут, и (2) «ощущение» разговора с коучем — тон и момент срыва обычно нужно несколько раз доитерировать на живых людях.

## Открытые вопросы (не решено)

- Точная числовая метрика успеха на 90 дней
- Юридическая форма приёма оплаты из РФ и Европы одновременно
- Стек хостинга/деплоя бота (предположительно тот же VPS, что у личного агента, но отдельный процесс)
